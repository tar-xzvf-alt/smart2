# Смарт-контракт аренды квартиры

Python-модель одного договора аренды: первый месяц и залог вносятся
в начале, один месяц долга допустим, два приводят к разрыву договора.
При обычном окончании из залога вычитаются долг и подтверждённый ущерб.
Подробности: [правила аренды](docs/rental-model.md) и
[таблица для ручного рисунка](docs/rental-transitions.md).

## Запуск

Нужен Python 3.10 или новее. Сторонние библиотеки не требуются.

```bash
python3 -m rental scenario examples/settlement.json
python3 -m rental scenario examples/break.json
python3 -m rental random --seed 42 --mode valid --steps 20
python3 -m rental random --seed 42 --mode any --steps 30 --save run.json
python3 -m rental scenario run.json
python3 -m unittest discover -s tests -v
```

`valid` выбирает допустимую команду либо ожидание. `any` может выдавать
любую команду, включая неподходящую для текущего состояния. Оба режима
используют ту же модель, что и подготовленный сценарий. Seed позволяет
повторить опыт; сохранённый JSON фиксирует конкретные события.
Генератор не оптимизирует поведение и не перебирает все последовательности.

В JSON `terms` задаёт месячную плату `rent`, залог `deposit`, число
месяцев `months` и длительность месяца `month`. В `batches` задаются
неубывающие метки `at` и списки `commands`. Пустой список только продвигает
время. Для дробного времени используется строка, например `"13/4"`.
Параметр `amount` — сумма для `start`, `pay` и `inspect`, число добавляемых
месяцев для `extend`; у `settle` параметра нет.

## Инструменты

- Python и `unittest` — модель автомата, сценарии и проверка траекторий.
  Tkinter можно использовать для просмотра таблицы и трассы, если
  понадобится интерфейс.
- Solidity 0.8.26 и Foundry — будущий контракт и локальные тесты в EVM.
  Конфигурация Foundry предусматривает `contracts/` и `test/`;
  эти каталоги появятся при реализации.
- Граф автомата рисуется **только вручную**. Код не строит граф
  и не рассчитывает его раскладку; Graphviz не используется для графа.

Не использовать с реальными средствами.
